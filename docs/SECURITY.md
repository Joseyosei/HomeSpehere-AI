# Stage 09 security
Local single-installation owner + household-scoped viewers. All data APIs require sessions; public auth status/login/bootstrap registration and static assets only. First owner requires HS_SETUP_TOKEN, at least 32 random characters. After first account, bootstrap registration permanently closes; owner can create viewer accounts with explicit household IDs. No public self-registration, email verification, password recovery, MFA or internet deployment. Owner sees both demo and live data and global automation; viewer can read assigned households and chat only about those households. Integration discovery, automation and security logs owner-only. Existing automation admin bearer token remains required as additional gate. No tenant-level provisioning: independent customers must use separate deployments/databases.
## Setup
Generate a random token with node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))". Set HS_SETUP_TOKEN in private .env; npm run start:configured; open loopback dashboard, register first owner, sign in. Remove setup token after registration. Password 12–128 characters; scrypt N=32768,r=8,p=3, random 16-byte salt, 64-byte output. No password or token in audit. Sessions random 256-bit tokens stored SHA-256 hashed, absolute 24-hour expiry, one active session per account; logout revokes. HttpOnly SameSite=Strict cookie; Secure optional for future HTTPS, not enabled by default on local HTTP. CSRF header required for authenticated writes including AI chat. Host and origin checks reject nonlocal or cross-site requests; no CORS. Rate limits are process-wide fixed windows (600 API/min, 10 auth attempts/min, 2 concurrent password hashes); restart resets limits. Local-only architecture, not a public production security boundary.
## Audit
Account creation, login success/failure, logout, rejected authentication/origin/CSRF/role/household access and automation administrative requests. Last 100 visible to owner. Not tamper-proof; no retention yet. Migration 3 adds users, memberships, sessions, security_audit. Protect SQLite files and backups with OS access controls. Do not commit .env or private data.
## API
GET /api/auth/status, POST /api/auth/register, POST /api/auth/login, POST /api/auth/logout, GET /api/auth/audit. Viewer registration requires owner session+CSRF and explicit household IDs; bootstrap requires setup token. All existing data endpoints require session; AI parsed household is checked. Automation requires owner+CSRF for mutations and existing admin bearer token.
