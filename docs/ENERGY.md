# Stage 07 — energy intelligence
Local, read-only analytics over one explicitly selected meter. No paid APIs. Never sum overlapping devices. Daily and month-to-date buckets use UTC (not local billing days); partial final buckets are included. No time-of-use tariff support yet.
## Configuration
Set optional values in .env and restart with npm run start:configured. HS_ENERGY_CURRENCY (default GBP); HS_IMPORT_RATE and HS_EXPORT_RATE (currency/kWh); HS_STANDING_CHARGE (currency/day); HS_CARBON_FACTOR (kg CO2e/kWh). Blank/unset means unknown; 0 is valid. Use your actual tariff and a documented grid emissions factor; no official rates assumed. Config applies to all selected households and historical periods, so changing it reprices historical estimates. No tax adjustment, tariff versioning or live carbon feed. Standing charge is prorated by elapsed UTC days, not supplier billing policy. Import cost and export credit use independently measured grid streams; net cost requires all three components. Incomplete coverage can understate totals; no missing interval imputation.
## Forecast
Simple transparent rolling mean of up to seven sufficiently covered days from the last 14 completed UTC days. Minimum 3 days with >=90% coverage, no extrapolation for missing intervals. Seven-day estimate is daily baseline x7; not weather-aware or a guarantee. Historical walk-forward MAE is reported when at least four usable days exist. Demo has only 24h of samples and normally cannot forecast. No artificial history inserted.
## Peak and solar
Peak is max observed good power sample in period, not a demand-charge or half-hour peak. Solar advice requires >=90% coverage on solar and export. Export can include battery or other sources; no fabricated self-consumption or savings. Shift discretionary loads only when safe. Carbon is estimated operational grid import emissions using configured constant factor, not avoided or lifecycle emissions.
## UI/API
Energy intelligence panel: meter, UTC day/month, metric selector, keyboard/hover chart details, accessible readings table, refresh. GET /api/energy/tariff, GET /api/energy/report?household=demo&device=meter&period=day (or month). Report includes metrics, buckets, tariff, costs, forecast, peak and solar advice. Data retrieval bounded at 150000 readings per metric per report; oversized reports return 422. Localhost only, no authentication yet.
## Verification
npm test includes deterministic tariff, coverage, calendar, forecasting, solar, peak and HTTP integration checks. Real billing and forecasting accuracy require household-specific validation.
