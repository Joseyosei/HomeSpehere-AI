# Stage 06 — local household assistant
The assistant is read-only and evidence-grounded. Ollama selects IDs from a bounded, server-generated facts list; the server renders verified text rather than displaying raw model prose. No tools, SQL generated by model, device commands, cloud API, or persistent chat logs. Rule fallback works without Ollama. Answers are advisory, not alarms, diagnoses or verified billing.
## Start
Install Ollama locally from https://ollama.com/download. Run ollama pull qwen2.5:3b and ensure Ollama is listening at http://127.0.0.1:11434 (ollama serve if needed). Copy .env.example to .env and set HS_AI_ENABLED=1; npm install; npm run start:configured. Open http://127.0.0.1:8780 and use AI Assistant. Default model is configurable. Model availability and hardware performance vary. Use a locally downloaded model only; configure Ollama with cloud features disabled (OLLAMA_NO_CLOUD=1), do not enable remote models or expose its port. HomeSphere restricts its configured endpoint to loopback but cannot verify whether a separate local service forwards requests. AI off by default.
## Data and privacy
Selected demo/live household only; device labels replaced by ordinal IDs before model request. Latest good samples within 30 minutes and last 24h energy summaries; capped at 50 devices and 120 facts, no aggregation of overlapping meters. History (up to six messages) is held in browser memory and sent with each question, cleared on household switch or clear button. Do not type credentials or sensitive data; prompts are passed to local Ollama. No chat storage in HomeSphere. Ollama runtime logging is separately configured. Local server is not an authentication boundary; keep it loopback-only.
## Anomaly and recommendations
Median/MAD of up to 96 good prior samples within 24h, at least eight, threshold max(metric floor, 4 x 1.4826 x MAD). Heuristic, no seasonality or calibrated false positive rate. No alert delivery. Recommendations use deterministic thresholds, not learned preferences. Missing or offline current readings not treated as zero. Coverage accompanies estimated energy; no bill forecasts.
## API
GET /api/ai/status; POST /api/ai/chat with JSON {household,question,history:[{role,content}]}. Limits: 16 KiB request, 1000 characters question, 6 history entries of 1500 chars, one concurrent request, one-second admission interval, 20s model timeout. Output includes mode, source, asOf, answer, evidence, recommendations, anomalies, limited and notice. No model prose rendered. Errors or invalid evidence trigger deterministic fallback.
## Tests
npm test covers mock Ollama selection, invalid IDs, local fallback, source isolation, anomaly threshold, configuration and HTTP origin checks. This is not a live model benchmark or hardware validation.
