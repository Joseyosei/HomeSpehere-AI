# Stage 15 — mobile pairing
The native app pairs with a separate opt-in HTTPS listener, not the public Vercel preview or browser API. Owner signs in locally and selects the account and household, generates a single-use 256-bit pairing code (5 min), transfers it privately to the phone, then the phone redeems it for a 30-day read-only bearer credential. One active pairing per account, maximum 10 active device credentials per account. SQLite stores SHA-256 hashes, never raw credentials. Device keychain/Android Keystore via Expo SecureStore stores credential. Owner can revoke from local dashboard; mobile sign-out attempts remote revocation before local deletion. If offline, revoke from owner dashboard. No mobile account password entry; owner-authorised pairing is authentication. No automatic refresh; re-pair at expiry. Every request rechecks account household access. Owner access still global on local browser; mobile fixed to one household even for owner. Gateway endpoints cannot execute commands or access AI/admin endpoints.
## Network setup
Keep browser server on loopback. In private .env set HS_MOBILE_ENABLED=1, HS_MOBILE_BIND to your Mac's specific private IPv4 address (or 127.0.0.1 for local testing), HS_MOBILE_PORT=8443, HS_MOBILE_ORIGIN=https://<your-trusted-hostname>:8443, HS_MOBILE_TLS_KEY and HS_MOBILE_TLS_CERT to local PEM files. Certificate SAN must match hostname and be trusted by both native devices. Use a properly managed trusted certificate; never disable TLS verification or add cleartext exceptions. Private key chmod 600. Firewall restrict port to intended LAN clients; no router port forwarding. Node HTTPS min TLS1.2. Host matching, no cookies or browser Origin, fixed-window global rate limits. Native fetch redirect:error requested; platform behavior requires physical validation; only pair with a trusted gateway. No certificate pinning. No public deployment. Restart server; open local dashboard, Mobile pairing section. Copy code to native Settings and pair. iOS local network permission description included; Android trust behavior depends on platform CA configuration. Physical-device TLS and pairing not verified yet.
## API
GET /mobile/v1/status; POST /mobile/v1/pair {code,name}; authenticated GET/DELETE /mobile/v1/session; GET rooms, devices, latest, history, energy, energy/report under /mobile/v1/. Household forced to credential scope. Browser owner endpoints GET /api/mobile-admin; POST /api/mobile-admin/pair {userId,household}; POST /api/mobile-admin/revoke {id}, session and CSRF required. Schema 4. Logs record pairing issuance/redeem/rejection, scope denial and revocation without secrets. No private data caching. Native dashboard still synthetic until Stage 16 connects readings. Test with npm test and mobile npm test; bundle checks are not signed native builds.
