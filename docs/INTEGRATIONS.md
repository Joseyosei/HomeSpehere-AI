# Stage 05: read-only integrations
Home Assistant REST discovery and polling (default 15 seconds); MQTT exact-topic event ingestion. No service calls, publish commands, network scanning, or automatic MQTT discovery. HA discovery lists sensor entity IDs and units; only explicitly mapped entities persist. MQTT topics are manually configured. No hardware required for demo.
## Configure
Node 22.13+. Run npm install (MQTT client dependency). Copy .env.example to .env, edit locally, then npm run start:configured. On POSIX chmod 600 .env; on Windows restrict permissions via ACL. Never commit credentials. Alternatively set environment variables or HS_HA_TOKEN_FILE / HS_MQTT_PASSWORD_FILE pointing at private files. Restart to rotate credentials. HTTPS and MQTTS required by default; HS_ALLOW_INSECURE=1 permits plaintext only for trusted isolated development networks (credentials exposed on wire). Use trusted certificates or NODE_EXTRA_CA_CERTS, never disable verification. Use a dedicated HA non-admin account and a broker user with subscribe-only ACL on exact topics. HA token is not guaranteed to be read-only upstream; application performs only GET. Server remains localhost only.
## HA
Set HS_HA_URL, token and mappings. Discover via GET /api/integrations after startup. Use sensor entity IDs, select actual site consumption vs solar/import/export deliberately; do not sum overlapping meters. Last reported/updated source timestamp preserved. Polling cannot capture transitions between polls, and duplicate timestamps ignored. Failed requests retry with exponential delay up to 5 minutes. Poll errors are redacted.
## MQTT
Set HS_MQTT_URL, username/password and mappings. Broker must publish JSON like {"value":22.4,"unit":"C","ts":1760000400000}; UTC epoch milliseconds mandatory. Only exact mapped topics subscribed at QoS 1. Client retries every 5 seconds, resubscribes after connection. Retained messages keep their original timestamp; duplicates ignored. Payload size limited to 4096 bytes at application layer. No arbitrary broker discovery. No publishing.
## Mappings
HS_MAPPINGS is JSON array of {adapter,key,device,name,metric}. device is stable identifier; several metrics can share a device. One mapping per device+metric. Metrics and units: consumption/solar/grid_import/grid_export W or kW; temperature C/°C/°F; humidity/battery %. Unknown/missing stored as null; unsupported units rejected. Source separation: live household and live-prefixed IDs, demo remains intact. Devices marked offline on transport failure; online is last observed mapped sample, not a guarantee of device reachability. Staleness reported separately. Dashboard selector switches households; live values with several matching devices are not aggregated automatically.
