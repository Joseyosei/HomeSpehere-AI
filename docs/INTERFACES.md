# Stage 10 interfaces
Responsive dashboard, mobile/tablet breakpoints, system/light/dark appearance, comfortable/compact density and reorderable/hideable overview widgets. Preferences contain only layout choices and are browser-local, not account synced. Display mode enlarges overview cards and hides chat, automation, account details and configuration; exit via button or Escape. Fullscreen is optional and browser-dependent. Display mode is not an authorization boundary: use a viewer account on shared displays. Authentication remains required. No native iOS/Android/TV package or remote LAN access yet.
## PWA
Manifest, 192/512 PNG icons, service worker and offline fallback. On localhost Chromium can install via browser UI or Install app when supported. iOS Safari supports Add to Home Screen where available. HTTPS needed for non-loopback secure contexts. Server currently binds localhost; physical phones/TVs cannot access another computer's localhost. Stage 12 must address authenticated HTTPS LAN deployment before physical-device use. Service worker caches explicit public shell assets only, never APIs, credentials, chat or telemetry. Offline navigation shows generic offline page; live data cannot be retrieved offline. Existing page hides dashboard on network-offline event; server errors handled by refresh. Browser localStorage only holds layout preferences. No background synchronization.
## Tests
npm test for preference and route checks; npm run test:ui after npx playwright install chromium for browser login, theme, widgets, display mode, mobile width and offline navigation. CI includes Chromium. No claim of actual smart TV or physical mobile testing.
